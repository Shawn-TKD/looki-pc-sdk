# 本地优先的 Looki AI 工作流

## 项目目的

这个项目的主要目的不是替代 Looki 的全部产品体验，而是把用户拥有的设备变成一个
可由个人电脑和 Agent 调用的采集端。照片、录音和视频可以从 Looki 直接下载到本地，
再交给 Codex、Claude Code、本地语音识别或视觉模型处理。

这样做带来三个直接结果：

1. **数据路径可控**：原始媒体可以只存在于 Looki 和用户电脑，不需要先经过厂商云端。
2. **处理方式可组合**：用户可以选择本地模型、自己的 API 或完全离线的脚本。
3. **设备寿命不依赖单一客户端**：即使官方 App 的工作流发生变化，已验证的本地能力
   仍可以由 SDK 调用。

“本地优先”表示默认先落到用户控制的存储中，并不承诺所有模型都离线。若 Agent
调用云端模型，媒体或转写文本是否上传仍由所选模型和工具决定。

## 推荐架构

```text
Looki L1
  │
  ├─ RFCOMM / LCMP：身份认证、状态查询、拍照和录制控制
  │
  └─ 临时 Wi-Fi / HTTP：媒体目录与原文件
                 │
                 ▼
        inbox/YYYY-MM-DD/
        ├─ *.jpg
        ├─ *.m4a
        ├─ *.mp4
        └─ manifest.json
                 │
        ┌────────┼─────────┐
        ▼        ▼         ▼
       ASR      VLM      媒体元数据
        │        │         │
        └────────┼─────────┘
                 ▼
       Markdown / SQLite / 向量索引
                 │
                 ▼
          Codex / Claude Code
```

SDK 目前覆盖图中最上面的设备连接和下载部分。目录监听、增量导入、ASR、视觉理解和
长期索引属于下一层应用，不应耦合进蓝牙协议实现。

## 可以先做的应用

### 自动媒体收件箱

Agent 唤醒设备、读取媒体清单，只下载尚未出现的文件，并按拍摄日期归档。原文件保留，
生成内容写入同目录的旁车文件，避免修改照片、音频和视频本身。

### 录音转写与日记

对新 M4A 生成带时间戳的转写；将同一时间段的照片、录音和视频组合成一份 Markdown
日记。用户可以先在本地审阅，再决定是否加入长期记忆库。

### 图片和视频整理

为 JPG 生成场景、人物和物体描述；为 MP4 抽取关键帧后生成摘要。模型输出可以作为
搜索索引，原媒体仍留在本地目录。

### Agent 主动采集

Codex 或 Claude Code 可以通过 CLI 调用 `photo`、`audio-start`、`audio-stop` 等命令，
再下载刚生成的媒体。这使 Looki 成为 Agent 可以调用的现实世界传感器。

## 隐私边界

- `*.looki-binding` 是设备所有者凭据，只应加密保存和点对点迁移。
- 临时热点名称和口令属于会话信息，不写入公开日志。
- 原始抓包可能包含认证材料、网络配置和个人信息，不进入公开仓库。
- 媒体下载目录应由用户明确指定；SDK 不自动上传媒体。
- 使用云端 ASR、VLM 或 Agent 前，应根据所用服务决定是否提供原始文件。

## 下一步实现

推荐把本地 AI 部分实现成独立的 `looki-agent` 应用，依赖本 SDK，而不是把模型调用写进
协议层。第一版只需完成：增量下载、文件去重、音频转写、图片描述、按日期生成
Markdown。这样既能被 Codex 和 Claude Code 读取，也便于以后替换模型或存储系统。
